# Design System: HRRL Activities

This file records two visual worlds that share one token file (`frontend/app/app.css`).

- **The Evidence Room** is the employee world: entry, player, review, result, leaderboard, projector and certificate. Its values are the defaults on `:root`, and `.evidence-ui` re-applies them wherever an employee screen appears inside the admin (the Preview dialog). Each section below opens with it.
- **The Admin Console** is the `/admin/*` world, built on Microsoft Forms and Microsoft 365 conventions. `useAdminTheme()` (`frontend/app/lib/admin-theme.ts`) puts `.admin-ui` on `<html>` while an admin screen or the sign-in page is mounted, so portalled dialogs, menus and toasts follow it. `.admin-ui` swaps the font stacks and radii and re-points the shared tokens. In the frontmatter its tokens carry an `admin-` prefix, except the brand and status families, which keep their code names (`brand`, `ok`, `bad`, `warn`). Each section closes with an **Admin Console** subsection.

Where the Evidence Room text describes admin screens (the graphite rail, the workspace tab bar, the three-pane builder, the dashboard and publish splits, admin panels, status badges and code chips, `gutter-admin`), it records the admin look the console replaced. On `/admin/*` the Admin Console subsections govern, and the Evidence Room's rules, its Do's and Don'ts included, bind only the employee surfaces and `.evidence-ui` previews. The two worlds meet in the red-flag map: the console frames it, and the plate and markers inside it stay Evidence Room.

## Overview

**Creative North Star: "The Evidence Room"**

Each scenario is an exhibit laid on a table under good light. The employee inspects it, decides, and then sees exactly where the red flags were: numbered yellow tent markers drop onto the screenshot itself, and an evidence log beside it says what each one shows. The admin sees the same markers toned by how often the workforce missed them. Everything in the system serves that inspection: a graphite frame that recedes, a cool concrete ground, white work surfaces, and colour held back until it means something.

The density is operational, not promotional. These are work surfaces for refinery staff on phones and shared desktops and for a security team at office desktops: hairlines instead of shadowed cards, 1 to 2px corners, one sans family whose weights carry the hierarchy, and a mono for anything that has to be read character by character. Motion is spent on the reveal, where it carries the lesson; everywhere else a state change is a 150ms colour shift.

The world refuses the category default for quiz apps: a centred quiz card with a percentage progress bar, confetti and a blue SaaS shell. It also refuses decoration: no gradients, no glass panels, no side-stripe callouts, no kicker labels above headings.

**Key Characteristics:**

- Graphite shell, concrete ground, white work surfaces.
- Marker yellow is reserved for the one primary action, the current selection and the evidence markers.
- Manila is paper: codes, exhibit tags and notes you carry with you.
- Red and green mean outcome state only, and travel with a glyph and a word.
- Atkinson Hyperlegible Next for everything; Atkinson Hyperlegible Mono for codes, IDs and addresses.
- 1 to 2px corners, 1px hairlines, exactly two shadows.
- The tent marker and the exhibit tag are the signature devices.

## Elevation & Depth

Flat by default and tonal by structure. Surfaces separate from the ground by white against concrete and a 1px ring or hairline; the graphite frame sits at the same plane, not above it. Only two shadows exist, and they mean two different things: the evidence lies on the table, and some things float above it. Everything else that looks like a shadow is a keyline doing contrast work.

### Shadow Vocabulary

- **Plate** (`box-shadow: 0 18px 40px -28px rgb(26 28 30 / 0.45)`): the evidence plate, the phone evidence strip and the certificate sheet. A long, tight shadow under the lower edge: the exhibit is lying on the table.
- **Pop** (`box-shadow: 0 12px 28px -14px rgb(26 28 30 / 0.38), 0 2px 4px -2px rgb(26 28 30 / 0.12)`): anything that floats: dialogs, alert dialogs, popovers, select and dropdown menus, the response sheet, a row being dragged.
- **Field keyline** (`box-shadow: 0 0 0 1px var(--graphite)`, or `var(--evidence-red)` when invalid): thickens a focused field's border to 2px without a glow.
- **Selection keyline** (`box-shadow: inset 0 0 0 1px` in graphite, ledger green or evidence red): doubles the border of a selected, right or wrong option row.
- **Evidence keylines**: region marks carry `0 0 0 1px rgb(26 28 30 / 0.85), inset 0 0 0 1px rgb(26 28 30 / 0.5)`; tent markers carry `drop-shadow(0 2px 1px rgb(0 0 0 / 0.25))`; the tapped hotspot point carries a 3px white halo.

### Named Rules

**The Two Shadows Rule.** Only the plate and things that float get shadows. Panels, option rows, notes and cards separate from the ground by tone and a 1px ring.

**The Keyline Rule.** Anything drawn on top of a screenshot carries its own graphite keyline or halo, because the evidence underneath can be any colour.

### Admin Console

Layered, the Fluent way: cards lift off the grey ground on a soft two-layer shadow instead of a ring, and floating layers sit higher on a deeper version of the same shadow. Cards have no border. Inside a card, depth is tonal: the Ground 2 section header strip, Ground answer boxes and the QR well.

#### Shadow Vocabulary

- **Card** (`box-shadow: 0 0 2px rgb(0 0 0 / 0.12), 0 1px 2px rgb(0 0 0 / 0.14)`): every card. Lists, the stat row, summary and settings cards, builder cards, the sign-in card, answer cards in the response drawer. CSS var `--elev-card`, utility `shadow-card`.
- **Card hover** (`box-shadow: 0 0 2px rgb(0 0 0 / 0.12), 0 4px 8px rgb(0 0 0 / 0.14)`): a collapsed question card under the pointer, the one card that lifts, because clicking it opens it.
- **Pop** (`box-shadow: 0 0 2px rgb(0 0 0 / 0.12), 0 8px 16px rgb(0 0 0 / 0.14)`): menus, select lists, dialogs, alert dialogs, sheets and toasts. It is `--elev-pop` under `.admin-ui`, so the shared `shadow-pop` utility picks it up.
- **Save bar** (`box-shadow: 0 -4px 12px rgb(0 0 0 / 0.06)`): the sticky settings save bar, casting upward over the cards it floats above.
- **Field keyline** (`box-shadow: 0 0 0 1px var(--brand)`): a focused field's border turns Brand Blue and the keyline doubles it, through the re-pointed `--graphite`. The question-prompt field, the title-card fields and the section title field use a Brand Blue bottom border instead.
- **Edit ring**: the question card being edited carries a 2px Brand Blue ring rather than a deeper shadow.

#### Named Rules

**The Lift Rule.** Cards rest on the card shadow and floating layers on pop; nothing else casts a shadow except the save bar and the switch thumb. Only a collapsed question card lifts on hover.

## Shapes

Hard-edged evidence-room furniture. Corners are 1px on surfaces (panels, plates, option rows, chips, notes, nav items, review cells, skeletons) and 2px on controls (buttons, inputs, select triggers, dialogs, menus, popovers, tooltips, toasts). The only 4px corner is the data end of a chart column or meter bar, whose base stays square. Circles appear only where the form is a dot: radio indicators, status dots, the verdict disc, the hotspot point and the switch.

Borders are 1px hairlines. The 2px stroke is reserved for marks on the evidence (region marks, hotspot answers); option indicators use 1.5px. A dashed border means not yet, or the answer was here: unanswered review cells, a missed correct option, a hotspot answer region, a chart threshold.

Two silhouettes are the world's own. The **tent marker** is a trapezoid front face with a darker side face, so it reads as a folded card standing on the evidence rather than a badge. The **exhibit tag** has an arrow-cut left end (a clip-path polygon cutting 10px to a point) and a 7px punched hole.

### Admin Console

Softly rounded, in Fluent proportions; `.admin-ui` sets `--r-xs` to 2px, `--r-sm` and `--r-md` to 4px, and `--r-lg` and `--r-xl` to 8px, so the shared `rounded-*` utilities follow. Controls are 4px (buttons, inputs, select triggers, menu items, dialogs), and so are the containers that sit inside a card (message bars, radio cards, question-type tiles, answer boxes, the QR well). Cards, toasts and the sign-in card are 8px. Pills, status badges, count chips, the avatar, the switch and the ends of the tab underline are fully round. 2px remains for small hover targets (the sort header) and the option rows of the question editor.

Answer indicators keep their form: single choice is a circle, multiple choice a 2 to 3px square. Chart bars and columns round only their data end (4px) and keep a square base. Card edges are shadow, not stroke; strokes are 1px hairlines (row dividers, the activity header's bottom border, the save bar's top border) or 1px inset rings (pills, the Scheduled and Open badges, radio cards, question-type tiles). The title card carries an 8px Brand Blue band across its top, clipped by the card's corners: the one place colour meets a card edge.

### Spot the Red Flags (interactive)

The live form of the evidence: employees draw a box around what they think is wrong, adjust it, and confirm it; the server judges each box.

- **Drawing:** drag on the plate to draw a box (marker-yellow 2px frame with a graphite hairline outside and in, marker-yellow 15% fill: the same frame as a revealed flag). A plain tap marks nothing; a graphite status pill at the plate's top-left says "Drag to draw a box around the red flag." and fades after about 2.5s. Pinch-zoom stays live; when zoomed, a pressed-state Hand button switches between drawing boxes and moving the view.
- **Adjusting:** a drawn box keeps four corner handles (12px white squares with a 2px graphite border and 28px hit areas) and moves when dragged by its body. A graphite action bar sits 8px below it (above it near the bottom of the plate; hugging the box's edge near either side) with a marker-yellow **Check** button (**Mark it** while results are held) and a ✕ that removes the box. Enter confirms, Escape removes, arrow keys move it by 0.5% and Shift with arrow keys resizes it. Handles, frame weight and the bar are counter-scaled, so they keep their size at any zoom.
- **Size limits:** boxes run from 1% to 60% wide and 40% tall. A box past the limit turns into a dashed evidence-red frame with a "Too big" tag, and the action bar says "Box one thing at a time" instead of offering Check.
- **Judging:** a box finds a flag when it takes in at least 40% of the flag (padded 1% each side) without the flag being under 12% of the box, or when it sits at least 60% inside a large flag. The best fit wins, so a tight box around a button inside a banner finds the button. One box finds at most one flag.
- **Hit:** the box resolves into the flag's region with its numbered tent dropping in (marker yellow during play). Numbers are the flag's position in the key, so they never renumber at the reveal.
- **Miss:** a dashed evidence-red box with an ✕ at its centre stays where it was drawn, entering with a short horizontal shake (`miss`, 420ms ease-out-expo).
- **Results held:** recorded boxes stay as neutral graphite frames with a white halo; nothing says whether they hit.
- **Scoreboard** (`SpotPanel`): "Red flags found n of N" in display weight; one tent per flag (muted "?" until found); wrong guesses left as filled graphite dots that empty to red outlines; a one-line status that stamps in (marker-wash for a find, red-wash for a miss, ground-2 for a repeat).
- **Reveal:** every flag tones found (ledger green) or missed (evidence red) on the plate and in a labelled list with "Found" / "Missed" text, so the state never rests on colour alone.

### Motion (reveal choreography)

- **Easing:** ease-out-expo, cubic-bezier(0.16, 1, 0.3, 1), for every keyframed entrance.
- **Region draw** (520ms): each region wipes in from its top-left corner (clip-path), 90ms apart.
- **Marker drop** (420ms): each marker falls 14px, scales from 0.9 and fades in, 120ms after its region.
- **Stamp in** (260ms): rises 6px and fades in; used for evidence-log rows (200ms, then 90ms apart), the next clue, the wrong-try note and the resume-code panel.
- **State changes:** 150ms ease-out on colour, border and the 1px button press; overlays fade and scale from 95% over 200ms.
- **Loading:** pulsing Concrete 2 blocks in the shape of the content; a spinner inside the acting button.
- **Reduced motion:** a global rule cuts every animation and transition to 0.01ms with one iteration and turns off smooth scrolling. Entrances use fill-mode both, so markers, regions and log rows land on their final frame at once.

Held by default: warning (or info before anyone submits) with a small primary Publish results; after publishing: success with the time and an outline Hide results; shown right away or admins only: info with Change in Settings. Publish results and Hide results each confirm in an alert dialog that says what employees will see.
- **Stat row:** one card of three stats 40px apart (Responses, Average score, Typical time): a 13px Ink 3 label, the value at 28px semibold tabular Ink, a 12px Ink 3 note (3 still answering, 64% passed); Download (outline, with a menu of Excel workbook and CSV file) on the right.
- **Score columns:** the Scores card holds a 150px column chart: columns at most 24px wide and 2px apart, a 4px round data end and a square base, a hairline grid at zero, half and max, 11px Ink 3 tabular ticks. Columns are Brand Blue; ranges below the pass mark are Admin Line Strong, and the card says so (Grey bars are below the 60% pass mark). Every column is a focusable target with a tooltip, and a screen-reader table carries the same data.
- **Answer bars:** each question card (1. prompt in 15px semibold, n responses in 12px Ink 3, then % answered correctly coloured Ok from 70%, Warn from 40%, Bad below) lists one row per option: the label, a 10px bar on a Ground 2 track with a 4px round end, and count · % in tabular Ink 2 / Ink 3. The correct option's bar is Ok and its label is semibold Ink with an Ok check (and "correct answer" for screen readers); every other bar is Brand Blue. From 640px the row is three columns (minmax(0,1fr) label, a 6 to 16rem bar, a 5.5rem value); below it the bar drops to its own full-width line.
- **Red-flag map:** a card titled Which red flags people missed: the Evidence plate with each flag's region and tent marker toned by miss rate, beside a list of flags (20px marker, label, Missed by n% · Question 3) whose hovered row takes Brand Tint, a Most missed line and a three-marker legend. The section pills switch screenshots.
- **Response drawer:** a right sheet on the ground. A white header with the name at 20px, the employee ID, facts (Score, Time taken, Submitted: 12px Ink 3 labels over 13px semibold values), a More details disclosure (resume code, certificate number, IP address), a Hide from leaderboard switch and an outline Let them retake. Below, white answer cards (8px, Card shadow): Question 3 in 13px semibold Ink 3 with the verdict on the right (an Ok check and Correct · 1, a Bad cross and Wrong or Partly right, Needs marking in Warn), the prompt in 14px semibold, the answer in a Ground box, Correct answer: … when wrong, and a Points box with Save mark for written answers.

#### Settings

- **Section card:** a 16px semibold title and hairline-divided rows.
- **Setting row:** what it is on the left (14px semibold label, 13px Ink 3 hint, a 13px semibold Bad error), the control on the right; when space runs out the control drops beneath the label. Dependent settings indent 24px. Switch rows put the switch on the right of the whole row.
- **Radio cards:** the results release choice is a stack of 4px cards with a 1px inset Line Strong ring (Ground on hover), each a radio, a 14px semibold title and a 13px Ink 3 line; the chosen card is Brand Tint with a Brand Blue ring. The first option, After I publish them (recommended), is the default.
- **Save bar:** only while there are unsaved changes or errors, sticky at the bottom, white with a top hairline and the save-bar shadow: You have unsaved changes (or an error message bar), then Discard (outline) and Save (primary) on the right.

#### Share Sheet

A right sheet: Share in 20px semibold with the status badge and a status sentence; a warning message bar listing what to finish before sharing, each with a Fix link; When can people take part? with Opens and Closes fields (optional, India Standard Time) and the actions Open now or Schedule (primary), Close now or Reopen (outline), Back to draft (ghost); then the Link: a read-only 13px field with Copy, the QR code (168px, Admin Ink on white) in a 4px Ground well, Download QR code, Open as employee and Leaderboard for a projector.

#### Overlays, Toasts and Focus

- **Dialogs and alert dialogs:** white, 4px corners, a 1px Line Strong border and the Pop shadow over a 50% black scrim; 18px semibold title, 14px Ink 3 description, Cancel (outline) then the confirm button (primary, or Bad for Delete) at the end.
- **Menus and selects:** white, the Pop shadow, 4px items in 14px with Ground on focus.
- **Toasts:** white with Ink text, a 1px Line border, 8px corners and the Pop shadow; descriptions in Ink 3. Messages are short past-tense confirmations (Link copied, Results published, Settings saved).
- **Focus:** a 2px outline offset 2px. Buttons, switches and selects use Admin Ink (the `--ring` token); links, pills, tabs and tiles take Brand Blue from the base rule; fields swap the outline for the Brand Blue border and keyline.
- **Selection:** Brand Tint 2 behind Ink.
- **Motion:** state changes are 150ms colour and border shifts, the 1px button press and the card lift; menus and dialogs fade and scale from 95% over 200ms; sheets slide in over 500ms and out over 300ms; loading is a spinner in the acting button or a pulsing skeleton. Nothing in the console is choreographed; the reveal motion belongs to the Evidence Room, and the global reduced-motion clamp applies here too.

## Do's and Don'ts

### Do:

- **Do** give each view one marker-yellow action (#f2c230 with #1a1c1e text): New activity, Continue on entry, Check answer, Submit answers, View certificate. Moving on (Next, Continue, Finish) is the graphite ink button.
- **Do** set codes, employee IDs, resume codes and quoted addresses in Atkinson Hyperlegible Mono, and compared numbers in tabular numerals.
- **Do** put evidence on the white plate with the plate shadow, zoom controls and the full-screen viewer, and collapse it to the 144px tap strip on phones until the reveal.
- **Do** reveal red flags as numbered tent markers on the evidence with a matching numbered evidence log, linked by hover in both directions.
- **Do** pair red and green with a glyph and a word: the verdict disc with a check or cross, plus Correct or Not quite.
- **Do** keep text at Ink 3 (#5f676c) or darker on light surfaces and Shell Muted (#a9afb2) or lighter on graphite.
- **Do** keep employee touch targets at 44px or more: option rows 48px, primary buttons lg (44px) or xl (48px), review cells 44px, rating squares 48px.
- **Do** separate surfaces by tone and 1px hairlines: white panels with a 1px Line ring on the concrete ground.
- **Do** use the 2px graphite focus outline with a 2px offset on light surfaces, and mark graphite regions `.on-shell` so focus turns marker yellow.
- **Do** keep reveal motion on ease-out-expo with the 90ms stagger, and let the global reduced-motion clamp land every animation on its final frame.

### Don't:

- **Don't** use marker yellow as a panel background, as decoration, or as text on a light surface, where it is 1.7:1.
- **Don't** use manila for actions, or red and green for anything except outcome state and errors.
- **Don't** put a kicker or eyebrow above a heading; meta (code chip, status, counts) goes beneath the title.
- **Don't** use gradients, glass panels or decorative blur. The only blur is a small legibility blur behind 95%-opaque sticky controls.
- **Don't** use side-stripe or left-border callouts; notes are full washes or ringed white cards, and quoted messages are fully bordered boxes.
- **Don't** round surfaces past 2px or chart data ends past 4px, and don't use pills except for dots, radio indicators and the switch.
- **Don't** add chart hues beyond Data Blue, Line Strong and Ledger Green; the leftover --chart-2 to --chart-5 variables are not part of the system.
- **Don't** use the stock shadcn Badge, Tabs, Checkbox or chart tooltip as shipped; they still carry pill and soft-shadow defaults. Use StatusBadge, CodeChip, the workspace tab bar and the option row.
- **Don't** build the category default: a centred quiz card, a percentage progress bar, confetti, or a blue SaaS shell.
- **Don't** render phishing evidence as live HTML, or draw, retype or recolour the HRRL and CISO Office logos; evidence is an image on the plate, and the brand is the supplied logo files under the White Ground Rule.

### Admin Console

These bind `/admin/*`. The lists above bind the employee surfaces and `.evidence-ui` previews.

#### Do:

- **Do** give each console region one filled Brand Blue button (#0f6cbd, white text): New activity, Share, Publish results, Save, Open now; everything else is outline or ghost.
- **Do** put console content in white 8px cards on the card shadow over the #f5f5f5 ground, with no card borders.
- **Do** keep building and settings in one centred column (800px Questions, 760px Settings) and list pages at 1120px.
- **Do** number questions 1, 2, 3 straight through the activity, call sections Section 1, Section 2, and show status as Draft, Scheduled, Open and Closed badges with a dot.
- **Do** keep "Publish" for results only: activities are opened (Open now, Schedule), closed (Close now, Reopen) and taken back to draft.
- **Do** state where results stand in a message bar at the top of Responses, and confirm Publish results and Hide results in a dialog.
- **Do** pair console status colour with a word or glyph: badge dot and word, a check and Correct, a cross and Wrong, a check on the correct answer's bar.
- **Do** draw the correct answer's bar in Ok green with a check and every other bar in Brand Blue; score columns below the pass mark are Admin Line Strong.
- **Do** turn console lists into stacked rows below 640px with the ⋯ menu visible, and give grid columns `minmax(0, 1fr)` so no page scrolls sideways.
- **Do** lay settings out as rows, label and hint on the left and the control on the right, and show the save bar only while something is unsaved.
- **Do** set console page titles and stat values at 28px semibold (36px line), body at 14px, and every emphasis at 600.

#### Don't:

- **Don't** bring Evidence Room furniture into the console chrome: no graphite rail, marker-yellow buttons, manila tags, exhibit letters, CASE codes, S1·Q01 code chips or tent markers outside the red-flag map and the Preview.
- **Don't** use Microsoft logos, product names or trademarks in the console; the only logos are HRRL's and the CISO Office's, and the product name is set in type.
- **Don't** add a second column, outline pane or side preview to the builder; Preview is a dialog.
- **Don't** use Brand Blue for anything but the account avatar, actions, selection, the active tab, links, focus and chart data; never as a panel fill or heading colour.
- **Don't** use green, amber or red in the console without a word or glyph, or for anything but status, answers and errors.
- **Don't** let a console page scroll sideways, or hide the row menu on phones.
- **Don't** border console cards, or add shadows beyond card, card hover, pop and the save bar.
- **Don't** set console text in mono except strings people type (passwords, ID patterns, number answers).
